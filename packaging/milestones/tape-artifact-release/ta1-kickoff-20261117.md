## TA.1 acceptance: two distinct tracks

**Track A — two logical datasets on a fresh scratch SL tape:** Prepare one unique new scratch AWS image with a fresh six-character VOLSER, write two ordered standard-labeled logical datasets (a small FB80 bootstrap-like text fixture and a small PDS IEBCOPY unload), `LABEL=(1,SL)` and `LABEL=(2,SL)`. Prove that the first survives the second; inspect `VOL1`, `HDR1/HDR2`, `EOF1/EOF2`, data blocks and physical filemarks; independently restore/compare *both* payloads. Inspect Hercules device versus guest allocation/demount at the step boundary; characterize `VOLUME=RETAIN` and `DISP=PASS` only if actual evidence requires it.

**Track B — `RECFM=U` load-library path:** Separately establish IEBCOPY unload/restore of an `ICINT19` load library `PO/U/0/6144` to a **new** scratch DASD PDS and prove directory, exact source/restored comparison where supported, and executable GO from **the restored** load library. The prior JOB 9060 directory plus JOB 9061 development-source execution establish neither byte identity nor restored GO. Use the accepted scalar/vector MR10 test only after the restored STEPLIB target is independently verified. Keep Track B media/targets separate unless a later explicit design choice combines them.

## Non-negotiable safety and execution sequence

1. **Preflight and design only first.** Inspect existing Git-controlled tools/JCL, MVS tape unit availability, actual `hetinit`/`hetmap` syntax, observed `0480` history (not guaranteed current), MVS `D U,TAPE`, volume allocation and prior demount behavior. Design source fixture names, distinct scratch target PDS names, a new unused image path under `mvs-state/tape/`, an unused six-character scratch VOLSER and expected JCL/DCBs. Document them for owner review before any stateful command.
2. **Explicit owner permission for scratch operations** is mandatory: initialize and mount a **new** image, run guest IEBGENER/IEBCOPY jobs, allocate scratch datasets, and any subsequent unmount/remount. Never initialize, append to, or overwrite an existing AWS image; never use existing live BCPL source/object/load PDSes as output.
3. Prefer one tightly controlled, fail-closed two-dataset experiment. Stop on unconfirmed tape position, mount status, wrong VOLSER, JES failure/timeout, unexpected label/filemark, collision or ambiguous completion. Do not automatically retry or resume an incompletely written volume; preserve failed media and evidence.
4. For each accepted step capture JES/job IDs, RC, utilities' messages, physical labels/blocks/filemarks, MVS unit state, source/restore DCBs, independent comparisons and immutable scratch-media SHA-256. Never infer success from `hetmap` or JES RC alone.
5. Run code/unit checks in an assistant-controlled workspace before committing. Commit source, JCL, tests and reviewed decisions directly to GitHub `main`; do not create local branches or untracked files on the user's checkout. User-facing command blocks are only for MVS-facing operations. Private evidence belongs to ignored `workarea/`, virtual tape to `mvs-state/tape/`, tracked contracts and results to `packaging/`. Keep console output concise.

## Boundary of TA.1

TA.1 **does not** produce the final distribution, choose a release version/VOLSER, freeze a candidate manifest, waive source/rights audits, ship the unfinished native-running compiler, or authorize publication. TA.0's 14/14 object readback and JOB 9060/9061 qualified development-load results remain accepted; no repeat required absent evidence of defect.
