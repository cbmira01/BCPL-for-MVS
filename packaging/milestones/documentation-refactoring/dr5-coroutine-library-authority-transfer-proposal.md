## Native public interface reconciliation

Reviewed [COHDR](../../../bootstrap-toolchain/library/coroutines.h), [COROUTIN](../../../bootstrap-toolchain/library/coroutines.bcpl), [BCPLCO](../../../bootstrap-toolchain/asm/bcplco-production.asm), [Global Number Registry](../../architecture/global-number-registry.md), [CO.5 installation evidence](../coroutines/co5-installed-production-pass-20261115.md), and [installed-only verifier](../../../tools/coroutines/verify-installed-production.py). COROUTIN is the separate Coroutine Support Library; BCPLCO is its Core Runtime bridge, not BLIB or an optional System Extension.

The supported initialization sequence in the accepted [installed application](../coroutines/candidates/co3-delete-reuse/source.bcpl) explicitly initializes CO3ROOT, CO3CURR and CO3LIST to zero before CO3INIT. BCPLMAIN paints unset globals with nonzero sentinels; CO3INIT checks CO3ROOT before allocating the root. Therefore the reference's current broad prohibition on application writes to state needs the explicit one-time initialization exception. This is a documented caller precondition, not authorization to reset a live context or add automatic initialization. Check CO3INIT's nonzero result before proceeding. CO3INIT allocates root bookkeeping; it does not create a worker stack.

The declaration, linked CSECT and BCPL global binding are distinct. The installed verifier uses a guarded application-generation adapter that binds the external COROUTIN aliases and BCPLCO entries in the application export trailer; IEWL links installed objects read-only. This is not a BCEX/BCRG optional-package selection. The [production library preparation](../../../tools/coroutines/prepare-production-library.py) and [application adapter](../../../tools/coroutines/run-co3-delete-reuse.py) establish the supported mechanism. Do not imply that including COHDR alone or merely including both objects populates callable globals. G!289–294 are public procedures, G!295–297 state, G!298–300 private machine bridge entries. The Registry continues to own these assignments and collision restrictions.

| Public call | Supported contract and source limits |
| --- | --- |
| CO3INIT() | One root initialization with required zero state; returns root or zero on refusal/allocation failure. No reset/reentrant initialization promise. |
| CREATECO(FN,SIZE) | From initialized root only; valid callable FN; SIZE=1024; primes worker then returns handle without executing the user FN body until called. Returns zero for invalid size/state, bounded capacity or returned allocation/bridge initialization failure. Frees descriptor on stack allocation failure; frees stack and descriptor on CO2INIT refusal. Unexpected first-transfer mismatch has no general recovery contract. |
| CALLCO(C,A) | For valid known-live inactive worker, establishes parent, transfers A and later returns resumed value; native self/busy rejection -2. Not arbitrary pointer validation. |
| COWAIT(A) | In worker with parent, clears current parent association, yields A, later returns the incoming value; native root/no-parent refusal -3. |
| RESUMECO(C,A) | In worker with parent, gives that parent to a valid inactive target, clears own parent and transfers A; resumes with incoming value when later activated. Native root/no-parent -3, selected invalid target/busy -998. Busy refusal precedes state mutation. |
| DELETECO(C) | Root-only, known-live registered inactive and parent-unreferenced worker; TRUE on success, FALSE on rejected conditions. Revocation precedes unlink and freeing worker stack/descriptor. Do not use pointer after deletion, even if allocation address is reused. |

Source-observed details: native CREATECO allocates GETVEC(27) for combined lifecycle/context bookkeeping and GETVEC(1087) for 1024 safe words plus 256 bytes clearance; neither private size is an application descriptor/stack-allocation ABI. BCPLCO establishes a synthetic caller and checked generated entry, snapshots 16 GPRs, restores STKLIM/APLIMIT byte limits and G!54/55 word bounds before resuming code without MVS services during transfer. Root limits are restored when root resumes. No universal PSW/preservation mask, unchecked entry, preemption or overlapping calls.

The raw CO2WDONE trampoline marks a returned machine-level worker procedure terminal; supported COROUTIN instead supplies CO3BOOT, which repeatedly calls FN with values obtained from COWAIT. A user FN's ordinary return yields its result through CO3BOOT and permits another invocation on a later CALLCO. Do not confuse machine-bridge terminal-context refusal (historical CO.1/CO.2 experiments) with this public library behavior.

## MR10 boundary

[Canonical MR10 coroutine source](../../../mr10-kit-compiler/library/coroutines.bcpl) uses local globals 6–8 and 91–95 and the explicit arena-based allocator. Accepted pair programs initialize their own root descriptor (CURRCO, COLIST, root parent -1) and HEAPINIT; native initialization is not portable to MR10. CREATECO constructs a valid frame at P=C+3 with saved continuation P!1=COBOOT. Ordinary FN return is yielded through COBoot's repeated COWAIT/FN loop. MR10 CALLCO busy refusal is -999, while RESUMECO busy refusal is -998; do not import native self/root/no-parent/registry protection into MR10. MR10's DELETECO does not implement the native revocation-before-FREEVEC registry contract and dereferences nonzero descriptor pointers before membership verification. Valid/live preconditions apply. This is not a transfer of the separate MR10 allocator or non-coroutine library API.
