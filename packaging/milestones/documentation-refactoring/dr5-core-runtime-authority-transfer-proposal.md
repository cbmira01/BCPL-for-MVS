### Startup and native ABI

Source: [BCPLMAIN](../../../bootstrap-toolchain/asm/bcplmain.asm), historical [CGHDR](../../../richards-bcpltape/bcplib/bcpl/cghdr), [CO.1 qualified acceptance](../coroutines/co1-formal-acceptance-and-co2-transition-20261113.md). Record these explicit details in chapter 2, in addition to existing tables:

- G!0 is 699 (maximum index, not 700 or a callable address); unassigned slots are initialized to the historical sentinel X'C7D3F000'+4*N. Trusted compiler-generated trailer pairs are (global byte offset, relocated entry address), scanned backward to a zero-address sentinel. Application maximum/entry-offset checks use 2796 bytes; BLIB entry-offset check uses 800 bytes (G!200), not a BLIB allocation entitlement. These are observed bounds, not comprehensive malformed-trailer validation.
- Writer sequence: application, BLIB, native assignments, optional registrar before START. Preserve conditional G!76: linked BLIB WRITEF takes precedence when supplied, WRITEST is fallback only while G!76 is unset. BLIB linker symbol remains required. Historical [JOB 2199](../../archive/runtime-extensions/runtime-extensions-r0-g76-job-2199-evidence-20261021.md) and [JOB 2220](../../archive/runtime-extensions/runtime-extensions-r0-g76-noexport-job-2220-evidence-20261021.md) establish the two scoped paths, not arbitrary overlap permissions. Registry ownership remains independent.
- START receives no argument values; R0 and R6–R10 initialized to zero, R1–R3 to 4096/8192/12288, R4 to the entry, R5/R15 to initial workspace, R11/R12 to system/global vector bases. R13 is MVS save-area linkage. Ordinary generated entry saves R4–R6 in the callee frame, whose first three words hold entry, prior P and continuation. Ordinary return restores R6 from current P+8, prior P from current P+4, then R4 from restored P. R7–R10 are first four arguments and R7 returns function value. No all-register, PSW or arbitrary assembler preservation guarantee.
- System-vector offsets 0 return, 20 count-only skip, 40 FINISH, 60 checked entry, 80 combined checked/counting skip-only. Checked entry establishes P from W, validates positive word-aligned inline byte count, rejects frame end above STKLIM, accepts equality in this reconstructed source, restores entry base and skips the fullword. Caller W advance is not full frame size. Combined checked/counting cannot be used for safe execution; no claim for arbitrary fabricated metadata or unchecked workspace overflow.
- G!52/53 are word-address bounds of the main generated program; G!54/55 are allocated stack extent, not safe limit. SAVEAREA is a word pointer; only selected consumers and G!6!29/G!6!48 fields are established. Root initial marker/clearance details are implementation observations; not a guarantee of historical INUM or exact high-water readings.

Evidence includes ordinary native linkage cases 12–26, 32–33, separately compiled/assembled modules 25–26, checked cases 48–52, BLIB census JOB 1304 and current accepted production panels. Case 33 verifies caller base restoration. CO.1 is a qualified native ABI/stack baseline; do not import candidate-only context sizes into the public contract.

### Storage, byte primitives and APTOVEC

Source: [BCPLMEM](../../../bootstrap-toolchain/asm/bcplmem.asm), [BCPLBYTE](../../../bootstrap-toolchain/asm/bcplbyte.asm), [BCPLAPT](../../../bootstrap-toolchain/asm/bcplapt.asm). Preserve chapter 3.1's existing signatures, bounds and ownership. Explicitly distinguish returned GETMAIN failure (zero, list unchanged) and rejection of invalid N (zero) from arbitrary MVS abend. Allocation limit 4194299 is arithmetic/address-domain bound, not available memory or promise of successful maximum allocation. Case [30](../../../tests/bootstrap/30-getvec-failure/README.md) exercises an unsatisfied conditional allocation, case [39](../../../tests/bootstrap/39-freevec-storage-release/README.md) establishes same-size reallocation after exhaustion/free, not exact physical accounting. Case [38](../../../tests/bootstrap/38-putbyte-getbyte-roundtrip/README.md) verifies an ordinary byte store/load. No arbitrary offset or pointer safety or zero-init promise.

APTOVEC takes a callable native entry F and last index N; R7/R8 inputs, temporary V begins at incoming W+16, callback W follows N+1 words, and callback linkage clearance is included in the check. It calls F(V,N) and returns the function result, storage not retainable. Source rejects N outside 0..16380 or W+4*N+36 above active APLIMIT; N=16380 is not guaranteed feasible. Caller must provide valid checked workspace and function, not arbitrary code address. [091](../../../tests/bootstrap/091-aptovec-nested-call/README.md), [092](../../../tests/bootstrap/092-large-aptovec/README.md) and [093](../../../tests/bootstrap/093-aptovec-stack-overflow/README.md) cover nested return, 9001 words and controlled overflow, not all argument or active-stack cases. CO.1/CO.5 context-switch coordination remains separate.

### Termination and completion

Current source paths, not reserved numerical namespaces:
- Normal FINISH selects zero unless an accepted finalizer failure changes it to 8. Explicit STOP(N) preserves requested status, including STOP(0), within the supported MVS completion-code domain; negative/out-of-range STOP is not established. Finalizers execute before IOFIN; then MEMDRAIN, MEMBIND(0), root GETMAIN release, MVS return. The already approved System Extensions contract governs finalizer specifics.
- Character-output overflow enters STOP(12). Checked-stack/APTOVEC overflow instead replaces pending primary output with STACK OVERFLOW and takes FINIMPL (normally RC0; finalizer policy still applies). D7's RC12 is historical candidate policy. Cases [52](../../../tests/bootstrap/52-controlled-stack-overflow/README.md) and 093 have retained D6-compatible expected GO RC0000 and D7 RC0012 oracles. Do not change either.
- Source-only exceptional paths: GTOOBIG RC16 and NOSTART RC20 invoke RELMEM without FINEXIT; GNOCORE RC24 returns before allocation acquired; STKFORM RC36 directly returns without usual explicit cleanup. BADRETN contains RC36/RELMEM path, but arbitrary erroneous START return is not guaranteed to reach that label (START has R6=0). Registrar rejection RC12 before START follows its accepted IOFIN/RELMEM path; no partial registration/finalization contract change.
- Cases 082, 084–089, 119, 128/129 demonstrate ordinary output and termination behaviors at their fixture scopes. [083](../../../tests/bootstrap/083-instrumented-storage-reclamation/README.md) remains expected SKIP in installed mode; historical JOB 6295 counted returns from test-copy reclamation macros, not independent proof of current production leak freedom. No new fault injection or deliberate malformed pointer execution required for transfer of the supported domain.

### Private interface reconciliation — source observations only

[MEMBIND design](../../archive/core-runtime/bcplmain-wip/bcplmem-g6-freebase-binding-interface-design-20261012.md) originally proposed preserving R10. Current MEMBIND starts BALR 10,0, does not restore R10, and BCPLMAIN saves/restores its own R10 at the startup call site (RELMEM also calls it after MEMDRAIN and does not rely on old R10). Treat R10 as clobbered, not preserved. MEMBIND receives R1 native byte address of an aligned writable publication word, or zero to unbind without writing the old slot; copies current list-head byte address into the slot. MEMDRAIN detaches/publishes successor before FREEMAIN, saves/restores R0–R3, R15 and R14 in explicit source, uses R4/R8/R9/R10 as working registers; does not free root storage. MEMSTAT writes four fullwords at R1, uses R10 as base and restores R14, no BCPL global. No comprehensive MVS macro register/condition-code contract is claimed; older private comments are not authoritative preservation masks. Case 123 verifies actual publication at limited scope. No private source or calling-sequence correction proposed by C. Preserve original design records unchanged; describe these source observations in the reference without making private interfaces normative.

## D — Newly identified provisional DEBUGINT discrepancy

Current BCPLMAIN DEBUGINT tests sign in R7. For negative input it loads '-' in R10 and branches to DBGAPND, which uses R7 for capacity and destination addressing. On return DBGCVT executes CVD 7,DECPACK without restoring the original argument. This is a source-confirmed loss of the negative operand, not yet observed in a fresh MVS job. IODIAG also appends to the primary pending record regardless of selected output and can return 12 on truncation; DEBUGINT ignores that result. Positive ordinary fixture output must not be mistaken for a signed/general formatting contract.

G!150 remains provisional and collides with historical FORMTREE:150. No allocation, support expansion or runtime correction is implicit. Recommend a separate small compiled BCPL probe comparing positive and negative DEBUGINT against independent historical BLIB WRITEN or an exact expected record on the installed runtime, then decide whether to make a minimal operand-preservation correction with focused MVS verification or document negative input outside supported scope. Do not change existing oracles to conceal a failure; no new numbered case without approval. C excludes DEBUGINT's detailed behavior so that this finding does not block unrelated supported contracts.
