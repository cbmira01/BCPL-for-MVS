## Repeated native failure: newline representation discrepancy

Owner-reported diagnostic result at revision `e9c9ff16f433f206edb96776bda949b5b3b14d48`, private run `run-_bo0h4kz`, source SHA-256 `1436cfb97cbaa05a7e636b947716661d5ae92632d1a19d85505358f80f26af63`, oracle SHA-256 `e400cd4fd4bbd8088e97f5fafa736a886ddb762738f8fc9d43c959b4a63e0c95`: native JOB 9493 ASMAP/LKED RC=0, GO RC=12, the same seven complete RP records and partial RP: DR5, with no ISO record. Both original native and diagnostic outcomes remain FAIL. The diagnostic's compiler identity was not included in the failure receipt, but its driver reached native submission only after the Cambridge zero-code gate.

The seven complete records contain 118 visible characters plus seven embedded newline bytes; the seven-character partial record reaches exactly 132 bytes. JOB 9490's recovered assembler has X'25' in every *N string. [Compiler adaptation](../../../../../bootstrap-toolchain/bootstrap-cambridge/make-demoted.py) CODE370 deliberately maps host newline 10 to octal #45 (decimal 37). [BCPLIO](../../../../../bootstrap-toolchain/asm/bcplio.asm) IOLF is fullword 10, IOMAX 132; IOWRCH compares the supplied word against IOLF before appending, and IOWFULL calls the STOP(12) exit. [Regressions 110](../../../../../tests/bootstrap/110-default-output-newline/source.bcpl) and [111](../../../../../tests/bootstrap/111-consecutive-output-newlines/source.bcpl) use explicit WRCH(10); the [accepted dynamic stream contract](../../../bcplio-dynamic-stream/BCPLIO-dynamic-runtime-contract.md) documents 10 as the delimiter and 133rd-byte overflow. Historical BLIB NEWLINE calls WRCH('*N'), and WRITEF passes literal characters to WRCH. These facts strongly support a newline-representation mismatch rather than a shift fault. The printer rendition does not establish actual physical record boundaries. Do not silently treat the original programs as passes or change accepted compiler/runtime code without owner design approval.

A separate native-records candidate preserves the original computation and formatting arguments, removes embedded *N from output format strings, calls WRCH(10) after each message, and independently reports both GETBYTE("*N",1) and the character literal '*N' (hypothesis 37,37). Its ten-record oracle is native-records.expected. Explicit-record success would establish the original language observations with this output convention and confirm the predicted newline values, not repair either failing candidate or prove raw QSAM record fidelity. The native-only --run-native-records option submits DR5CREC and RG902R; 902 is a private helper naming parameter, not a suite case. Offline Python compilation, source/oracle checks, mocked native routing, and arithmetic byte count passed. No target run has yet occurred for this new candidate.
