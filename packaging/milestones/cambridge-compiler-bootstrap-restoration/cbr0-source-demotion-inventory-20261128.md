### LEX literal qualification

The source strings have decoded lengths 152 and 179, counting their final double slash but excluding `*` newline whitespace `*` continuation syntax. MR10 SYN checks `CHARP=255`, handles that continuation syntax and allocates CHARV VEC 256 and WORDV VEC 100. Thus the generator's claimed 255-character limit does not itself explain these two splits. Other limitations in the compilation, textual INTCODE output, source record handling or loading are not excluded. These are source-derived measurements, not a successful compilation. Test the unsplit inputs with the preserved baseline before drawing a conclusion; retain the accepted transformation until a replacement is verified.

## 2. Diagnostic derivative inventory

`instrument_cg` adds seven listing-only diagnostic insertion sites: CGA SCAN dispatch (OP/SSP); CGB CGENTRY (label/name length), CGSAVE (N/SSP/STKCK), CGAPPLY (FNAP or RTAP, K/W offset/SSP), CGAPPLY safe frame (SAFEFRAME/BASEFRMSIZE); CGE GENSTKCK1 (slot label/TXTP) and GENSTKCK2 (label/frame words/bytes). CGC and CGD receive diagnostic banners but no extra instrumentation. CGA diagnostic input also receives the same production PK370 transformation. Each instrumented unit then receives the ordinary `write_unit` transformations. These are diagnostic derivatives, not production demotions. `check-cg370-diagnostic.py` requires at least one marker and exact equality of listing lines after stripping `* CG370-DIAG:`. Preserve selectable diagnostics, verify ordinary/diagnostic listing equality at changed scope, and do not infer identical binary object bytes solely from listing comparison. CBR.7 covers actual stack/counting behavior separately.

`bootstrap-host.bcpl` is a separate source module, not a `make-demoted.py` transformation. Its G!33 WRAPOUTPUT remembers a flag without implementing real host wrapping. G!39 FINDPARM opens CAMBPARM and installs wrappers over G!13 RDCH, G!11 SELECTINPUT and G!46 ENDREAD; G!15 UNRDCH replays one character, guards misuse and stream changes; G!26 SKIPREC reads until logical newline or EOF; G!29 DATE returns an explicitly packed three-word EBCDIC undated placeholder. Verify exact DATE field layout, not just displayed date text.

## 4. ICINT20 bootstrap dependency and candidate verification proposal

Historical MR10 TRN serializes string length and numeric character values into OCODE; MR10 CG `CGSTRING` emits numeric `C` directives, one for the length byte and one per character. Therefore the textual deck can encode character values independently of the current loader's packing. ICINT19 STC initializes CP=16 and packs two bytes into each 32-bit physical word; STW resets CP. ICINT20 candidate should test CP=32 and four-byte GETBYTE/PUTBYTE with independently expected layout. Preserve the historical deck text, not ICINT19 memory layout. This is a hypothesis for compatible decks, not a guarantee: numeric packed constants, word counts, global initializers, label addresses, alignment, embedded code assumptions and library dependencies need audit. Old BLIBI cannot be presumed four-byte compatible merely because it loads. Its source PACKSTRING returns N/2 and pads an even-length string. MR10 CG READOP uses packed-string comparison and must be verified if executed under ICINT20.

Proposed least-circular initial path (CBR.1): retain the verified ICINT19/MR10 construction as the seed; assemble/link ICINT20 privately; run hand-written textual decks independent of BLIBI, checking word, byte and string boundaries, label fixups, arithmetic, instruction dispatch and capacity. Generate candidate BLIBI from adapted maintained source using the preserved MR10 system; use a separately staged candidate ICLIB and exercise candidate library through ICINT20. Only then attempt an applicable MR10-generated Cambridge textual deck under ICINT20 with representation adaptations removed. Do not require an already working ICINT20-hosted MR10 compiler to build its first compatible library. The exact ABI, candidate dataset/member names, staging and promotion procedure remain design decisions for CBR.1/2; no installed or accepted component is replaced in this investigation. If tests demonstrate that the seed cannot generate compatible decks, return to the owner with a minimal justified adaptation rather than silently extending MR10.

MVS, IFOX, IEWL and JES evidence is mandatory for acceptance. Test raw words independently (e.g., C3 C65 C66 C67 yields 03414243 hex in one ICINT20 word), C runs terminated by a word directive or label, 0/1/3/4/7/8/255-byte lengths, padding, GETBYTE/PUTBYTE and adjacent word integrity, signed arithmetic, and program/stack capacity. Verify actual object bytes and independent native application output, not just self-consistent round trips. Preserve ICINT19 and MR10 source, textual decks and supported regression baselines. CBR.9 remains the final clean-room reconstruction and full regression acceptance.
