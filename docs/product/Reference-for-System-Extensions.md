# Reference for System Extensions

*Cambridge BCPL Programming System for MVS 3.8J*

**Status:** Chapter 1 is normative for shared QUERY v1 by [DR.5 owner approval](../../packaging/milestones/documentation-refactoring/dr5-query-authority-and-qsam-precedence-acceptance-20261127.md). Chapter 5.4 includes the owner-approved OPEN rollback precedence decision. Other existing contracts retain authority until individual reconciliation and explicit owner approval. Applies to native applications generated by the interpreter-hosted demoted Cambridge Compiler; not MR10 INTCODE or a native-running compiler. RC4 native distribution is work in progress. See [explanation](Explanation-of-System-Extensions.md) and [how-to](How-to-Use-System-Extensions.md).

## 1. Common conventions — globals, dispatcher, QUERY v1, vectors, errors and versions

This chapter governs the shared QUERY v1 public interface. The [original QUERY decision](../../packaging/archive/runtime-extensions/runtime-extensions-r0-query-abi-decision-20261021.md) is preserved as historical engineering evidence; the other [R.0 decisions](../../packaging/milestones/runtime-extensions/runtime-extensions-r0-owner-abi-decisions.md) retain their respective authority. Normally one dispatcher global; extra exports require documented exception. R7/R8/R9 carry first three arguments; signed result R7. Native words 32 bits; BCPL pointers are word addresses, linked assembler structures byte addresses. Caller supplies genuine accessible storage; no arbitrary pointer or dishonest capacity protection.

Opcode 0 QUERY is side-effect-free except successful writes. SERVICE(0,0,0) returns full size; SERVICE(0,V,C) queries with word capacity C. Package must already be linked and registered.

| Word | Format-1 prefix |
| --- | --- |
| 0 | Format = 1 |
| 1 | API major |
| 2 | API minor |
| 3 | Entire descriptor words (at least 6) |
| 4 | Bitmap: bit 0 = opcode 1, bit 31 = opcode 32 |
| 5 | Package capability flags |

Major/minor must match the linked BCEX descriptor; the three maintained packages report 1.0 in both places. Require compatible major, sufficient minor and necessary bits. G! declarations, linkage and registration are independent; QUERY does not discover absent packages. Unassigned bits zero; >32 needs documented appended map extension. Compatible descriptors preserve the meaning of all six prefix words, append fields and report the entire descriptor length; no partial-prefix success. Incompatible reinterpretation requires a new shared format version. An implemented opcode bit does not guarantee that its environmental prerequisites are satisfied.

| Condition | Return | Writes |
| --- | --- | --- |
| Null, zero capacity | Positive full size | None |
| Valid buffer, sufficient capacity | Positive full size | Exactly full descriptor; trailing words untouched |
| Nonnull, insufficient nonnegative capacity incl. zero | -1 | None |
| Unsupported nonzero opcode | -2 | No QUERY write required |
| Null/nonzero capacity or negative capacity | -3 | None |

Negative capacity is argument error before shortage. A nonnull vector must designate genuine accessible writable words: the implementations test null and capacity but do not generally validate a nonnull machine address. An invalid nonzero pointer is outside the supported domain. Ordinary semantics are package-specific; no common ordinary-operation result vector is imposed. Isolated JOB 2206 included two dispatchers and an eight-word descriptor. Accepted BCPLDEMO/BCPLTIME cases 160–162 and BCPLQSAM/BCPLDEMO case 170 exercise cross-package calls; case 163 verifies QSAM QUERY fields and error paths in both native profiles. These finite tests do not establish every package combination, every register invariant or an actual maintained extended descriptor. Side-effect-free QUERY excludes OPEN/I/O, clock reads, resource allocation, hidden initialization and package state changes.

## 2. Common registration and selection — BCEX/BCRG v1, limits, diagnostics, collision checks and finalization

### 2.1 Linked layouts

All numerical fields fullwords; identifiers uppercase blank-padded EBCDIC CL8; addresses relocated byte addresses. Independently linked trusted extents, aligned nonzero ordered spans and exact declared/calculated/actual size required.

| BCRG offset (bytes) | Field |
| --- | --- |
| 0 | CL4 BCRG |
| 4 / 8 / 12 | Version 1 / header 28 / total bytes |
| 16 / 20 / 24 | Selected N / required M / reserved zero |
| 28 | N descriptor begin/end pairs, 8 bytes each |
| 28+8*N | M required CL8 IDs |

| BCEX offset (bytes) | Field |
| --- | --- |
| 0 | CL4 BCEX |
| 4 / 8 / 12 | Version 1 / header 48 / total bytes |
| 16 | CL8 package ID |
| 24 / 28 | API major/minor |
| 32 / 36 / 40 / 44 | Exports K / finalizer address or zero / dependencies D / reserved zero |
| 48 | K pairs (global, entry address), 8 bytes each |
| 48+8*K | D records (CL8 required ID, required major, minimum minor), 16 bytes each |

| Limit | Value |
| --- | --- |
| N/M | 0–32 each |
| K | 1–8 |
| D | 0–16 |
| BCRG | 28+8*N+8*M; max 540 bytes |
| BCEX | 48+8*K+16*D; max 368 bytes |
| Aggregate | 12,316 bytes |
| Global | 1–699, if owned and assigned |

G!0 is metadata. Empty registry 28 bytes, N=M=0. Guard counts before arithmetic. The approved contract requires dependency-first order, exact major and minimum minor; no duplicate/self/cyclic dependency or unauthorized global collision. Actual application/BLIB/Core Runtime ownership ledger, not merely declarations. Retain verified G!76 precedence. Alignment/relocation alone cannot prove callable targets safe. The current registrar is single-task/nonreentrant; its corrected dependency-validation behavior and evidence are recorded below. All three maintained package descriptors are 56 bytes, K=1, D=0, API 1.0. BCPLQSAM alone declares a nonzero finalizer.

### 2.2 Validation and diagnostics

Per [Decision G](../../packaging/archive/runtime-extensions/runtime-extensions-r0-decision-g-contract-20261021.md): registry extent, header, counts/size; package extent, header, counts/size; identities/entries; ownership and dependencies. First offending linked record within category. Reject before START with RC12 and no optional globals published. The [registrar source](../../bootstrap-toolchain/asm/bcplrgs.asm) checks the effective G-slot sentinel and per-slot prior-writer ledger, rejects duplicate global numbers and callable entry addresses, and has a separate PUBLISH pass after validation. Numeric slot availability is not enforcement of the source-controlled Global Number Registry; link review must check package ownership. Package and required IDs are checked for blanks and duplicates, but full uppercase/padding syntax is a trusted build obligation, not a runtime-verified grammar.

| ID | Meaning |

| 1002 | Registry magic/version/header/reserved |
| 1003 | Registry count/size/length |
| 1004 | Package extent/alignment |

| 1006 | Package count/size/length |
| 1007 | Invalid/duplicate package identity |
| 1008 | Invalid/duplicate global or entry |

1000–1099 startup, 2000–2099 finalization; not JES RCs or package statuses. R.1 integrated acceptance follows isolated R.0 count/size JOB 2203; R.2 JOB 3092 tests a single dependency and negative cases, not every legal dependency count.

**DR.5 registrar corrections — installed and verified.** The earlier registrar rejected a distinct second dependency (self-comparison), read later descriptors before their structural validation, accepted a negative minimum minor, and compared a byte offset instead of the matched package ordinal. The corrected source validates all selected extents, then headers, then counts/lengths in separate bounded passes before identities/entries and dependency processing; it compares prior records from the table base and preserves the ordinal for order checks. Malformed required major (nonpositive) or minimum minor (negative) is 1014; well-formed incompatibility remains 1011. Private JOB 798 and installed JOB 802 passed all 18 assertions and finalization checks; JOB 801 installed and compared the object. The four numbered [Runtime Extensions regressions](../../tests/README.md) 194–197 protect these contracts in regular campaigns; all four passed on their first numbered production-profile MVS run, together with 146–158 (17 PASS). This establishes the exercised scope, not exhaustive dependency counts, arbitrary pointers or complete multi-fault precedence outside the structural categories.

### 2.3 Finalization and selection

No v1 initializer. Finalizers once in reverse order before IOFIN/MEMDRAIN. RGFINI consumes REGCOUNT before calling any finalizer, skips zero entries and continues after returned errors, retaining status 8 if any fails. BCPLMAIN converts that status to FINISH RC8 but leaves STOP(n) unchanged. MVS linkage: R1 points to 8-byte block (+0 reason FINISH=0/STOP=1, +4 STOP code); R13 save area, R14 return, R15 entry/status; preserve R2–R12/R13. Nonzero status -> 2001; ordinary FINISH RC8, STOP(n) retains n. No arbitrary abend recovery.

BCXSEL selects, BCXREQ selects/requires; duplicates suppressed, later requirements upgrade. IFOX BCXPRE + BCXCAT + selection + BCXPOST produces registry and INCLUDE PUNCH cards. Current [BCXCAT](../../system-extensions/bcx/BCXCAT.asm):

| Package | INCLUDE | Extent |
| --- | --- | --- |
| BCPLDEMO | EXTLIB(BCPLDEMO) | DMOBEG/DMOEND |
| BCPLTIME | EXTLIB(BCPLTIME) | TIMBEG/TIMEND |
| BCPLQSAM | EXTLIB(BCPLQSAM) | QSMBEG/QSMEND |

Unknown names MNOTE 8, 32 selection maximum. Source-mode catalogs use temporary DDs. Explicit application ENTRY and exactly one registry. No automatic dependency expansion. See [R.4](../../packaging/milestones/runtime-extensions/runtime-extensions-r4-closure-20261024.md) and [R.5](../../packaging/milestones/runtime-extensions/runtime-extensions-r5-closure-20261024.md).

## 3. BCPLDEMO — purpose, header, DEMOSVC, version, operations, parameters, results, linkage and limits

Permanent supported project-created reference, [owner decision](../../packaging/milestones/runtime-extensions/bcpldemo-supported-reference-decision-20261024.md); API 1.0. [bcpldemo.h](../../system-extensions/bcpldemo/bcpldemo.h): DEMOSVC:203, DEMO_QUERY=0, DEMO_GETVALUES=1. QUERY (1,1,0,6,1,0).

| Op | Arguments after op | Success | Errors |
| --- | --- | --- | --- |
| 0 QUERY | vector, word capacity | 6; common rules | -1/-3 |
| 1 GETVALUES | writable vector, word capacity | 3; values 10,20,30 | -1 shortage; -3 null/negative |

## 4. BCPLTIME — purpose, header, TIMESVC, time representations, operations, statuses and linkage

Accepted T.0/T.1; API 1.0 raw time, not calendar library. [bcpltime.h](../../system-extensions/bcpltime/bcpltime.h): TIMESVC:201, TIME_QUERY=0, TIME_STCK=1, TIME_MVS=2. QUERY (1,1,0,6,3,0).

| Op | Arguments after op | Success |
| --- | --- | --- |
| 0 QUERY | vector, word capacity | 6 |
| 1 STCK | writable vector, at least 3 words | 3; high word, low word, hardware CC 0–3 |
| 2 MVS | writable vector, at least 2 words | 2; raw R0/R1 from TIME DEC |
| Other | — | -2 |

Short -1, null/negative capacity -3; no partial write. Both ordinary operations require a nonnull writable vector, even at zero capacity; only QUERY permits the null/zero size probe. STCK returns three words even when hardware CC is nonzero; the caller interprets the CC independently of the positive word-count return. The source clears its scratch before STCK and captures CC immediately. Private doubleword-aligned scratch; no guarantee of doubleword-aligned BCPL VEC. TIME DEC SYS1.MACLIB expands SVC11; preserves permanent R0/R1. Raw bits, independent date/calendar decoding not established. No dependencies/finalizer; nonreentrant scratch.

[Source](../../system-extensions/bcpltime/bcpltime.asm) TIMDESC/TIMDISP, EXT_SOURCE(TIMEHDR), EXT_OBJ(BCPLTIME). [T.0](../../packaging/milestones/bcpltime/bcpltime-t0-closure-20261024.md) JOB 5436 after genuine JOB 5434 S0C4 and register preservation correction; JES DD attribution not verified. [T.1](../../packaging/milestones/bcpltime/bcpltime-t1-closure-20261024.md) installation 5455, catalog 5457, cases 159–162 source/installed. ## 5. BCPLQSAM — purpose, header, QSAMSVC, logical records, QUERY/OPEN/READ/WRITE/CLOSE/INFO, vectors, buffers, limits, devices, lifecycle, errors and JCL

Optional sequential logical-record I/O; not BCPLIO, not historical Cambridge API. [Public specification](../../packaging/milestones/qsam/bcplqsam-public-interface.md) governs, read dated design stages with later closures. API 1.0; [bcplqsam.h](../../system-extensions/bcplqsam/bcplqsam.h), QSAMSVC:200. QS_QUERY=0 returns (1,1,0,6,31,7). QS_CAP_FIXED=1, QS_CAP_VARIABLE=2, QS_CAP_CARRIAGE=4 (FBA, not VBA). Earlier Q.1 bitmap 25/flags 0 and Q.3 flags 3 are historical.

### 5.1 Request and result

Ordinary supported calls QSAMSVC(op,Q,R) require distinct, nonoverlapping accessible Q=VEC 3 (4 words), R=VEC 7 (8 words). Keep record buffers separate from these vectors. READ/WRITE require a positive accessible record-buffer word pointer even for zero-byte capacity/length; zero-length V/VB data does not authorize a null pointer. No capacity parameters for these vectors. Result is zeroed except documented fields on valid dispatch. Source rejects unsupported opcodes/nonpositive Q/R before clearing R; returned status is authoritative, do not inspect stale fields.

| Q word | Meaning |
| --- | --- |
| 0 | OPEN counted DD string pointer, otherwise opaque handle |
| 1 | OPEN mode, READ/WRITE buffer pointer, otherwise zero |
| 2 | READ byte capacity, WRITE byte length, otherwise zero |
| 3 | Reserved zero |

| R word | Meaning |
| --- | --- |
| 0 | Status (same as function result for valid ordinary dispatch) |
| 1 | OPEN handle, READ/WRITE byte count, READ required capacity, otherwise zero |
| 2 / 3 | Zero (no stable diagnostic encoding / reserved) |
| 4 / 5 / 6 / 7 | INFO format / effective DCB LRECL / BLKSIZE / max data bytes |

QUERY instead uses word capacity and positive size return.

| Operation | Q!0, Q!1, Q!2, Q!3 | Success |
| --- | --- | --- |
| 1 QS_OPEN | DD string, mode,0,0 | R!1 positive handle |
| 2 QS_READ | input handle, writable buffer, capacity bytes,0 | R!1 actual bytes |
| 3 QS_WRITE | output handle, readable buffer, length bytes,0 | R!1 accepted bytes |
| 4 QS_CLOSE | handle,0,0,0 | Handle retired |
| 5 QS_INFO | handle,0,0,0 | R!4–7 actual attributes; R!1–3 zero |

Modes QS_INPUT=1, QS_OUTPUT=2. No append/update/random access. DD name counted 1–8 characters; first alphabetic or @ # $, subsequent digits also; lowercase normalized, padded EBCDIC. Caller owns string. DD allocated beforehand; no dynamic allocation.

All undefined fields zero on valid ordinary dispatch. QSAM GET/PUT do not generally report normal R15 statuses; source uses EODAD/SYNAD paths. An unrecovered MVS abend is not an API status.

### 5.3 Data and geometry

One READ/WRITE = one logical record; exact bytes 00–FF including trailing blanks. No newline, translation, padding, truncation or string termination. QSAM owns blocking/deblocking. Caller owns valid storage and honest byte lengths.

| Enum | Format | Effective LRECL | Max data bytes |
| --- | --- | --- | --- |
| 1 QS_FMT_F | F | 1–1024 | LRECL |
| 2 QS_FMT_FB | FB | 1–1024 | LRECL |
| 3 QS_FMT_V | V | 4–1024 incl. RDW | LRECL-4 |
| 4 QS_FMT_VB | VB | 4–1024 incl. RDW | LRECL-4 |
| 5 QS_FMT_FBA | FBA | 1–1024 incl. ASA | LRECL |
| 6 QS_FMT_VBA | VBA | Unsupported | None |

Enums are not DCB flags. **1024 total private stage bytes per handle** is an implementation ceiling, not MVS-wide. V/VB max payload 1020, zero payload is successful data, RDW private, BDW excluded. FBA caller includes ASA byte 0; preserved, interpreted by MVS/JES2. Fixed WRITE length exactly LRECL; variable actual payload 0 through effective maximum. WRITE acceptance is not proof of final device delivery.

Source QCVFORM pre/post-OPEN checks exact RECFM values X'80' (F), X'90' (FB), X'40' (V), X'50' (VB), X'94' (FBA) after validating sizes. Positive BLKSIZE <=32760; F equals LRECL, FB/FBA integral multiple not smaller, V/VB at least LRECL+4. Source-observed, not all geometries tested. Unsupported format -9, incomplete/invalid geometry -6. RDJFCB, post-OPEN DCB check, conditional GETMAIN before publication. Compatible JCL geometry required; explicit DCB prudent if incomplete. MVS may abend on OPEN. INFO reports actual effective attributes, not copied JCL.

### 5.4 Handles, retry, cleanup and devices

Sixteen slots, tested 17th refusal. Positive opaque IDs never recycle on slot reuse; source stops after maximum positive ID. Interleave handles; no arbitrary duplicate-DD guarantee. Private DCB snapshots/stages, nonreentrant single-task.

READ shortage -1, R!1 required data bytes, caller buffer untouched, whole record staged. Repeated short retries no further GET; successful retry consumes pending record. EOF sticky until CLOSE, R!1=0, unchanged buffer. Successful READ only touches actual bytes. A malformed V/VB RDW (reserved halfword nonzero or length outside 4 through effective LRECL) sets sticky -12 until CLOSE; this is source-observed and not a claim that arbitrary malformed physical records reach this branch safely. CLOSE discards pending record. No public buffer ownership is transferred, and subsequent operations take a fresh caller pointer.

Successful CLOSE frees owned resources/retires ID. Returned -14 quarantines unusable handle and uncertain ownership: no blind retry or unsafe free. By [owner approval](../../packaging/milestones/documentation-refactoring/dr5-query-authority-and-qsam-precedence-acceptance-20261127.md), if OPEN fails after successful underlying OPEN and rollback CLOSE also returns an error, preserve the original primary OPEN/geometry/resource status. Publish no handle; quarantine uncertain resources, do not retry CLOSE or free potentially referenced storage, and report unresolved uncertainty through generic finalization under the existing FINISH/STOP policy. Do not infer the actual DCB open/closed state. No new status or result-field encoding; an identifiable returned error on directly requested CLOSE remains -14. DR.5 private numbered cases 198–200 verified injected stage refusal, real conditional GETMAIN refusal and combined primary-error/quarantine behavior. Cases 198 and 199 passed; combined JOB 1300 demonstrated the asserted behavior (expected GO RC8 and both diagnostic traces). After correction of the host registrar-message parser, retained-evidence automated replay passed at e9f0f7380fcf without a new JES job. The combined case verifies the now-approved policy under private instrumentation, not a genuine MVS CLOSE failure. Actual exceptional MVS CLOSE remains unverified. QSMFIN generic finalizer closes live handles, reports uncertainty, common FINISH/STOP policy. No arbitrary abend recovery.

Sequential F/FB, V/VB, FBA; selected PDS member where compatible. No U, VS/VBS, VBA, VSAM, BSAM/EXCP, physical blocks, keyed/random access, dynamic allocation, PDS directory management or STOW. Q.4 specifically verifies FB80 punch and FBA133 printer, independent dataset bytes plus device presentation, not arbitrary geometry or raw spool bytes.

[Assembler](../../system-extensions/bcplqsam/bcplqsam.asm): QSMDESC/QSMDISP, private core/I/O, QSMFIN one object. EXT_SOURCE(QSAMHDR), EXT_ASM(BCPLQSAM), BOOT_JCL(BCPLQSAM) installation, EXT_OBJ(BCPLQSAM) target. [Installation design](../../packaging/archive/qsam/qsam-q5-installed-reconstruction-20261101.md) records retired Q5QVFY deck, not current executable proof. Numbered 163–176 now support source mode in the production profile and installed mode in the historically named installed-r5-t1 profile.
